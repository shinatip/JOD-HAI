# LINE Bot: บันทึกรายจ่ายบัตรเครดิต

บอท LINE สำหรับบันทึกรายจ่ายแยกตามบัตร พร้อมสรุปยอดตาม **รอบบิลจริงของแต่ละบัตร**
(ไม่ใช่สิ้นเดือนปฏิทิน) รองรับผ่อนชำระหลายงวด และเช็ควงเงินคงเหลือ

## ฟีเจอร์
- เพิ่มได้หลายบัตร แต่ละบัตรมีวงเงินและวันตัดรอบของตัวเอง
- บันทึกรายจ่าย: เลือกบัตร → เลือกหมวดหมู่ → ใส่ยอดเงิน → ผ่อนหรือไม่
- สรุปยอดตามรอบบิลปัจจุบันของบัตร (แยกตามหมวดหมู่ มาก→น้อย)
- สรุปยอดรายปี (แยกตามเดือนที่ตัดบิล + ตามหมวดหมู่)
- เช็ควงเงินคงเหลือของแต่ละบัตร
- รายการผ่อนชำระ: ยอดต่อเดือนจะถูกคำนวณเข้ารอบบิลถัดไปหลังวันซื้อ และขึ้นบิลต่อเนื่องตามจำนวนงวด

## โครงสร้างโปรเจกต์
```
src/
  config/       LINE SDK + Supabase client
  utils/        คำนวณรอบบิล/ผ่อนชำระ, format ข้อความ
  services/     คุยกับฐานข้อมูล (users, cards, transactions, billing_items, summary)
  handlers/     ประมวลผล text message และ postback (ปุ่ม quick reply)
  bot/flows.js  สร้างข้อความ/quick reply ที่ส่งกลับให้ผู้ใช้
  index.js      Express server + webhook endpoint
sql/schema.sql  สร้างตารางทั้งหมดใน Supabase
```

## Setup

### 1) สร้างฐานข้อมูลใน Supabase
1. สมัคร/เข้า https://supabase.com สร้างโปรเจกต์ใหม่ //-- &g%3ZTJGfbs.q4k
2. ไปที่ **SQL Editor** → New query → วางเนื้อหาไฟล์ `sql/schema.sql` ทั้งหมด → Run
3. ไปที่ **Settings → API** คัดลอก `Project URL` และ `service_role` key (ใช้ service_role เพราะบอทรันฝั่ง server)

### 2) สร้าง LINE Official Account + Messaging API channel
1. ไปที่ https://developers.line.biz/console/ สร้าง Provider
2. สร้าง Channel ประเภท **Messaging API**
3. ในหน้า channel: เปิด **Use webhook** = ON, ปิด **Auto-reply messages** และ **Greeting messages** (กันชนกับบอท)
4. คัดลอก **Channel access token** (กด Issue ถ้ายังไม่มี) และ **Channel secret**

### 3) ตั้งค่าโปรเจกต์
```bash
cp .env.example .env
# แก้ .env ใส่ค่า LINE_CHANNEL_ACCESS_TOKEN, LINE_CHANNEL_SECRET, SUPABASE_URL, SUPABASE_SERVICE_KEY
npm install
```

### 4) ทดสอบในเครื่องตัวเองด้วย ngrok
```bash
npm run dev
# terminal อีกอันหนึ่ง
ngrok http 3000
```
คัดลอก URL จาก ngrok (เช่น `https://xxxx.ngrok-free.app`) ไปใส่ใน LINE Developers Console →
channel ของคุณ → Messaging API → Webhook URL = `https://xxxx.ngrok-free.app/webhook` → กด Verify

จากนั้นเพิ่มบอทเป็นเพื่อนด้วย QR code ในหน้า channel แล้วลองพิมพ์ "เมนู" คุยกับบอทได้เลย

### 5) Deploy ขึ้นจริง (Railway ตัวอย่าง)
1. Push โค้ดนี้ขึ้น GitHub repo
2. ไปที่ https://railway.app → New Project → Deploy from GitHub repo
3. ใส่ environment variables ให้ตรงกับ `.env` (Railway จะ set `PORT` ให้อัตโนมัติ)
4. เมื่อ deploy สำเร็จ จะได้ URL ถาวร เอาไปใส่เป็น Webhook URL แทน ngrok ในขั้นตอนที่ 4

## คำสั่งที่ใช้คุยกับบอท
| พิมพ์ | ทำอะไร |
|---|---|
| `เมนู` | แสดงคำสั่งทั้งหมด |
| `เพิ่มบัตร` | เริ่มขั้นตอนเพิ่มบัตรใหม่ (ชื่อ → วงเงิน → วันตัดรอบ) |
| `บัตรของฉัน` | แสดงบัตรทั้งหมด |
| `บันทึกรายจ่าย` | เริ่มบันทึกรายการใหม่ |
| `สรุปเดือนนี้` | สรุปยอดรอบบิลปัจจุบันของบัตรที่เลือก แยกตามหมวดหมู่ |
| `สรุปปีนี้` | สรุปยอดทั้งปีของบัตรที่เลือก แยกตามเดือน + หมวดหมู่ |
| `เช็ควงเงิน` | แสดงวงเงินคงเหลือของทุกบัตร |
| `ยกเลิก` | ยกเลิกขั้นตอนที่ทำค้างอยู่ |

## Logic สำคัญที่ควรรู้ (และปรับได้ตามต้องการ)

**การตัดรอบ**: รายการที่ซื้อ "ก่อนหรือวันเดียวกับ" วันตัดรอบของเดือนนั้น จะเข้ารอบบิลของเดือนนั้น
ถ้าซื้อ "หลัง" วันตัดรอบไปแล้ว จะเลื่อนไปรอบบิลเดือนถัดไป (ดู `src/utils/billing.js`)

**การผ่อนชำระ**: ยอดต่อเดือนถูกคำนวณด้วยตรรกะเดียวกับรายการปกติ คืองวดแรกจะขึ้นในรอบบิลถัดไปหลังวันที่ซื้อ
จากนั้นงวดต่อๆ ไปขึ้นบิลทุกรอบถัดไปจนครบจำนวนงวด เศษทศนิยมจากการหารจะถูกดันไปรวมกับงวดสุดท้าย
เพื่อให้ผลรวมตรงกับยอดซื้อจริงเป๊ะ

**วงเงินคงเหลือ (เช็ควงเงิน)**: ระบบนี้ **ยังไม่มีการบันทึกการจ่ายบิล** จึงใช้สมมติฐานว่า
ผู้ใช้จ่ายบิลเต็มจำนวนทุกรอบตรงเวลา ดังนั้น "ยอดที่กินวงเงิน" = ยอดซื้อทั้งหมด (รวมผ่อนเต็มจำนวนตั้งแต่วันซื้อ
ตามพฤติกรรมบัตรเครดิตจริง) **ลบ** ยอดที่ขึ้นบิลไปแล้วในรอบที่ผ่านมา (ถือว่าจ่ายแล้ว) ถ้าอยากติดตามการจ่ายบิลจริง
ต้องเพิ่มตาราง `payments` และปรับ `getCardUtilization` ใน `src/services/summaryService.js`

## แนวทางต่อยอด
- **Rich Menu** (เมนูรูปภาพติดล่างจอ) แทนการพิมพ์คำสั่ง — ตั้งค่าผ่าน LINE Developers Console หรือ Messaging API
- **LIFF dashboard** หน้าเว็บสรุปกราฟ/ตารางเวลาเปิดจาก LINE โดยตรง อ่านข้อมูลจาก Supabase ตัวเดียวกัน
- หมวดหมู่ที่ผู้ใช้เพิ่มเองได้ (ตอนนี้เป็น list กลางที่ตั้งไว้ล่วงหน้าในตาราง `categories`)
- แก้ไข/ลบรายการที่บันทึกผิด
- แจ้งเตือนอัตโนมัติก่อนวันตัดรอบ หรือเมื่อใกล้เต็มวงเงิน (ใช้ LINE push message + cron job)
